# Q-Crate Run Format v1

## Purpose

The run format is the durable boundary between high-rate UDP ingest and later
analysis. The recorder preserves arrival evidence first, publishes only
verified shots, and gives offline or live tools a fixed-width index that does
not require rescanning every UDP datagram.

```text
UDP arrival
   |
   +--> packets.qcdp          append before protocol decisions
   |
   +--> validate/reassemble
           |
           +--> samples.iq16  append complete payload, then flush
           +--> shots.qidx    append COMPLETE/INCOMPLETE record, then flush
           +--> run.json      atomic rename when the run closes
```

The journal is the forensic source of truth. The sample and index files are
derived publications and can be regenerated by a future replay tool. All
multi-byte fields in QCRJ and QIDX use network byte order. Sample words retain
the little-endian encoding declared by Data Plane v1.

## Files

### `packets.qcdp`

QCRJ v1 is byte-for-byte compatible with the existing Python receiver. Its
16-byte file header is followed by a 32-byte arrival record and the raw UDP
datagram for every accepted source-address packet. The detailed QCRJ tables
are in [`README.md`](README.md#packetsqcdp).

The record stores host monotonic receive time, source address, source port,
and exact datagram length. Journaling occurs before Data Plane decoding, so
malformed, foreign-run, duplicate, and conflicting datagrams remain available
for audit.

### `samples.iq16`

This is a concatenation of complete shot payloads in frame/sample order. No
headers or padding are inserted between shots. QIDX supplies each shot's byte
offset and length. The current reference application uses `IQ_S16_LE`: signed
16-bit I followed by signed 16-bit Q in each little-endian four-byte word.

The recorder flushes a complete shot's sample bytes before appending its QIDX
record. Consequently, a valid COMPLETE record never intentionally points
beyond durable sample data. A crash may leave an unindexed tail in the sample
file; readers must ignore bytes not referenced by QIDX.

### `shots.qidx`

QIDX v1 begins with a fixed 32-byte header:

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 4 | ASCII `QIDX`, `0x51494458` |
| 4 | 2 | version, 1 |
| 6 | 2 | header bytes, 32 |
| 8 | 2 | record bytes, 128 |
| 10 | 6 | reserved, zero |
| 16 | 8 | run ID |
| 24 | 4 | stream ID |
| 28 | 4 | reserved, zero |

Each shot has one fixed 128-byte record:

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 8 | shot ID |
| 8 | 4 | state: 1 COMPLETE, 2 INCOMPLETE |
| 12 | 4 | issue bit mask |
| 16 | 8 | first shot packet sequence |
| 24 | 8 | last shot packet sequence |
| 32 | 8 | first-sample timestamp ticks |
| 40 | 8 | first host receive time, monotonic ns |
| 48 | 8 | last host receive time, monotonic ns |
| 56 | 8 | sample-file offset, or `UINT64_MAX` when incomplete |
| 64 | 8 | published sample bytes, zero when incomplete |
| 72 | 4 | reconstructed frame count |
| 76 | 4 | samples per frame |
| 80 | 4 | unique DATA packets |
| 84 | 4 | received shot datagrams, including duplicates |
| 88 | 4 | byte-identical duplicate packets |
| 92 | 4 | packets observed below the arrival high-water sequence |
| 96 | 4 | missing packet sequences |
| 100 | 4 | reconstructed payload CRC-32 |
| 104 | 4 | accumulated sender integrity flags |
| 108 | 2 | Data Plane payload format |
| 110 | 2 | bytes per sample word |
| 112 | 8 | stream configuration ID |
| 120 | 8 | reserved, zero |

Issue bits are stable within QIDX v1:

| Bit | Name | Meaning |
|---:|---|---|
| 0 | PROTOCOL | malformed object or unsupported field combination |
| 1 | MISSING | packet-sequence gap or missing boundary object |
| 2 | CONFLICT | one sequence arrived with differing bytes |
| 3 | FRAME | frame/sample coverage or sender-total disagreement |
| 4 | CRC | absent or mismatching terminal payload CRC |
| 5 | SENDER | non-complete status or source/drop/overflow flag |
| 6 | TIMESTAMP | first-sample timestamp contract failed |
| 7 | CONTINUITY | run sequence, shot ID, or timestamp did not increase |

An INCOMPLETE record is intentional evidence, not an absent result. Readers
must never infer sample ownership from nearby offsets or attempt to expose
bytes for that shot.

### `run.json`

The manifest is written through a temporary file and atomic rename after the
receive loop closes. It records terminal/interruption state, complete and
incomplete shot counts, packet diagnostics, Linux receive-queue drops, socket
buffer sizes, and total published sample bytes. IDs are hexadecimal strings
to preserve all integer bits in JSON consumers.

`complete: true` is the run acceptance decision. A missing `run.json` means
the process did not close normally; QCRJ and committed QIDX records can still
be audited.

## Reader Rules

1. Reject unknown magic, version, header size, record size, nonzero reserved
   fields, or a truncated final record.
2. Treat QIDX as append-only and process only complete 128-byte records.
3. Expose sample bytes only for COMPLETE records whose offset and length fit
   inside `samples.iq16`.
4. Treat INCOMPLETE records as first-class loss/error events.
5. Use `run.json` for the final run decision, not merely the presence of
   complete shots.
6. Use QCRJ replay when validating a new analyzer or investigating any
   disagreement with QIDX.

These rules keep the recorder suitable as a product-facing acquisition
boundary while allowing the visualization layer to evolve independently.
