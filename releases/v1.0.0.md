# v1.0.0 — Networked Pulsed-IQ Analyzer

Q-Crate v1.0.0 is the first formal public release of the Q-Crate digital
instrumentation platform and the accepted completion point for its first
reference application, **Networked Pulsed-IQ Analyzer v1**.

This release proves a reproducible, heterogeneous, end-to-end measurement path
on the AMD Kria KV260: deterministic PL timing, R5 real-time supervision,
Linux DMA and networking, integrity-preserving host recording, and bit-accurate
IQ analysis.

![Accepted Q-Crate Networked Pulsed-IQ Analyzer](https://raw.githubusercontent.com/solomontesema/qcrate/v1.0.0/host/acceptance/images/dp5d-kv260-accepted.png)

## Highlights

- Reproducible Vivado project, bitstream, and XSA generation from tracked Tcl,
  SystemVerilog, configuration, and Python entry points.
- Fixed PetaLinux platform with validated 200 MHz stream/timing and 100 MHz
  control clocks.
- Explicit APB register pages and clock-domain crossings for command, event,
  status, interrupt, stream, and sequencer paths.
- Shared 64-bit hardware timebase and deterministic two-channel pulse
  sequencer.
- Cortex-R5 FreeRTOS/OpenAMP service with a versioned RPMsg command protocol and
  exclusive sequence lifecycle ownership.
- Bit-accurate DSP chain comprising a deterministic 200 MS/s synthetic source,
  29 MHz complex downconversion, and a 217-tap decimate-by-16 FIR producing
  12.5 MS/s Q1.15 IQ.
- Linux DMAEngine client with finite scatter-gather chains and an asynchronous
  finite-SG bank pool.
- Explicit `FREE -> FILLING -> READY -> USER_OWNED -> FREE` ownership. A bank is
  never reused while userspace owns unread measurement data.
- Frozen Q-Crate Data Plane v1 UDP protocol with run, stream, shot, frame,
  packet-sequence, timestamp, payload-format, and integrity metadata.
- Direct packetization from read-only DMA mappings without an intermediate
  userspace sample copy.
- Compiled host recorder with an immutable datagram journal, QIDX publication
  boundary, atomic manifests, and quarantine of incomplete shots.
- Live and offline analyzer for I/Q, magnitude, phase, constellation, spectrum,
  metadata, and instrument health, including bounded-memory navigation of long
  acquisitions.
- Machine-readable soak and recovery acceptance with exact DSP-model comparison
  of every published IQ word.

## Architecture And Ownership

Q-Crate deliberately assigns work according to timing and ownership:

- programmable logic executes sample-level timing, streaming, and DSP;
- R5-0/FreeRTOS validates and supervises deterministic sequence lifecycle;
- A53/PetaLinux manages DMA descriptors, coherent DDR buffers, Ethernet, and
  operating-system policy;
- the host records, replays, verifies, and visualizes measurements.

Bulk sample data never passes through RPMsg. Linux does not generate pulse
edges or sample timing. The analyzer remains outside the recorder's ingest
path, so closing or slowing the GUI cannot corrupt acquisition.

## Reproducibility

The release is source-based. Generated Vivado projects, Vitis workspaces,
PetaLinux/Yocto build trees, bitstreams, XSA files, firmware ELFs, SD-card
images, and raw acquisitions are intentionally excluded from Git.

The accepted versions are:

- Vivado 2024.2;
- Vitis 2024.2;
- PetaLinux 2024.2 with eSDK Update 1;
- AMD KV260 Starter Kit SDT BSP 2024.2;
- target `xck26-sfvc784-2LV-c`;
- Python 3.10 or newer for host automation and numerical tooling.

The
[release manifest](https://github.com/solomontesema/qcrate/blob/v1.0.0/releases/v1.0.0-manifest.json)
records the source tag, toolchain boundary, accepted evidence paths, and hashes.
Build and deployment procedures are versioned beside their owning subsystem,
starting with the
[KV260 platform guide](https://github.com/solomontesema/qcrate/blob/v1.0.0/kv260/README.md).

## Compatibility Boundary

Data Plane v1 and QIDX v1 are frozen by this release. Their existing byte
order, offsets, sizes, field meanings, packet types, and publication semantics
must not change incompatibly under version 1. Future incompatible layouts
require a new protocol or storage-format version.

## Scope And Limitations

Q-Crate v1.0.0 uses a deterministic synthetic ADC/channel model in RTL. It does
not contain or claim a completed physical ADC, DAC, RF, or analogue front end.
Consequently, this release makes no claim for analogue bandwidth, ENOB, SNR,
SFDR, clock jitter, impedance, calibrated voltage, converter synchronization,
or physical trigger accuracy.

The release also does not implement JESD204, an LVDS converter interface, PCIe,
a MicroTCA backplane, product safety, regulatory compliance, or production
deployment support.

## What This Release Establishes

v1.0.0 establishes a measured digital foundation on which a physical
instrument can be built without redesigning its control, timing, DMA,
networking, recording, and analysis ownership boundaries. The next focused
platform milestone is a hardware-independent acquisition-source contract. A
physical adapter should follow only after selecting a concrete converter and
measurement objective.
